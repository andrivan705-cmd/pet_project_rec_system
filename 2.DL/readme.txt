1. Постановка задачи
Задача осталась прежней: предсказать вероятность того, что пользователь поставит лайк просмотренному посту (бинарная классификация). Однако в этом блоке я значительно расширил признаковое пространство, применив современные методы глубокого обучения для извлечения смысловых представлений текстов постов и улучшил качество рекомендаций. В качестве финальной модели использован CatBoost, который позволил эффективно работать с категориальными признаками и достичь требуемого уровня качества HitRate@5 > 0.57.

2. Данные и подготовка
2.1. Генерация эмбеддингов постов
Я использовал предобученную модель DistilBERT (из библиотеки Transformers) для получения плотных векторных представлений текстов постов. Каждый пост был преобразован в эмбеддинг размерности 768 путём извлечения скрытого состояния специального токена [CLS].

python
tokenizer, model = get_model('distilbert')   # загрузка DistilBERT
embeddings = get_embeddings_labels(model, loader).numpy()
Благодаря этому шагу модель получила возможность «понимать» семантику текста, а не только оперировать поверхностными тематиками.

2.2. Уменьшение размерности и кластеризация
Эмбеддинги размерности 768 были сжаты до 50 главных компонент с помощью PCA, после чего применён алгоритм KMeans с числом кластеров n_clusters = 15. Для каждого поста были рассчитаны расстояния до центров всех кластеров (DistanceToCluster_0 … DistanceToCluster_14), которые стали новыми числовыми признаками.

Этот подход позволил выделить скрытые тематические группы постов и отразить степень принадлежности поста к каждой из них, что значительно повысило информативность модели.

2.3. Формирование обучающей выборки
Из таблицы feed_data были взяты только события типа view (просмотр) за период, ограниченный 9 миллионами записей. Целевая переменная target (лайк после просмотра) осталась без изменений. Обучающая выборка была обогащена:

Признаками пользователя: пол, возраст, страна, город, экспериментальная группа, ОС, источник.

Временными признаками: час и месяц просмотра.

Признаками постов: тема (topic), номер кластера (TextCluster) и расстояния до центров кластеров (DistanceToCluster_*).

3. Архитектура модели
В качестве финальной модели был выбран CatBoost Classifier — градиентный бустинг на деревьях решений, который превосходно справляется с категориальными признаками без необходимости их предварительного кодирования.

Ключевые параметры модели:

python
CatBoostClassifier(
    iterations=200,
    learning_rate=1,
    depth=2,
    random_seed=12345612,
    thread_count=-1,
    task_type="GPU"
)
iterations=200 — количество деревьев в ансамбле.

depth=2 — небольшая глубина деревьев, что предотвращает переобучение.

task_type="GPU" — обучение на видеокарте для ускорения вычислений.

Модель принимает на вход список категориальных признаков (object_cols), включая topic, TextCluster, gender, country, city, exp_group, hour, month, os, source. Остальные признаки (числовые) обрабатываются стандартным образом.

4. Процесс обучения
Обучение проводилось на выборке из 9 млн записей с использованием GPU.

Фреймворк: CatBoost (встроенная поддержка GPU).

Функция потерь: LogLoss (бинарная классификация).

Оценка качества на валидации: не применялась отдельная валидационная выборка, качество контролировалось по метрике HitRate@5 на отложенном тестовом наборе.

Регуляризация: малая глубина деревьев (depth=2) и использование категориальных признаков без one-hot-кодирования помогли избежать переобучения.

После обучения модель была сохранена в формате pickle (model.pkl) для последующего использования в сервисе.

5. Метрики и результаты
Основной целевой метрикой являлся HitRate@5 — доля пользователей, для которых хотя бы один реально лайкнутый пост попал в топ-5 рекомендаций.
В результате применения описанного подхода удалось достичь значения HitRate@5 > 0.57, что превышает минимальный порог (0.52) и подтверждает практическую значимость разработанной системы.

Сравнение с предыдущей ML-моделью:

ML-модель (XGBoost) показывала ROC-AUC ~0.65, но HitRate@5 был ниже.

DL-подход с эмбеддингами и кластеризацией позволил поднять HitRate@5 на несколько процентных пунктов, что говорит о лучшем учёте семантики контента.

6. Инференс и интеграция в сервис
6.1. Загрузка модели и признаков
При старте FastAPI-сервиса:

Загружается обученная модель CatBoost из model.pkl.

Из базы данных подгружаются:

таблица с признаками постов (andr_iv7_posts_info_features_dl), включающая кластерные расстояния и тему;

объединённые признаки пользователей (user_features), полученные слиянием public.user_data и кастомных признаков;

тексты и темы постов (post_texts) для формирования ответа.

6.2. Логика работы эндпоинта /post/recommendations/
Холодный старт: если пользователь отсутствует в таблице признаков, ему выдаются 10 самых популярных постов (по числу лайков).

Извлечение признаков пользователя: по user_id берётся строка с признаками, добавляются временные признаки (hour, month), удаляется user_id.

Формирование матрицы признаков: признаки пользователя размножаются на все посты из таблицы post_features, создавая полную матрицу для предсказания.

Предсказание: модель CatBoost вычисляет вероятности лайка для каждого поста.

Отбор топ-N: выбираются limit постов с наибольшей вероятностью.

Формирование ответа: к каждому посту добавляются текст и тема из post_texts.

Важно отметить, что структура признаков строго соответствует обученной модели (порядок колонок и типы данных), что гарантирует корректную работу.

7. Что сделано лично мной
Генерация эмбеддингов: реализовал пайплайн получения эмбеддингов постов с помощью DistilBERT, включая токенизацию, батчирование и извлечение скрытых состояний.

Признаки на основе кластеризации: применил PCA для снижения размерности и KMeans для кластеризации, создал признаки расстояний до центров кластеров.

Выбор и настройка модели: обучил CatBoost на GPU с оптимальными гиперпараметрами, добившись требуемого качества.

Интеграция в сервис: разработал код загрузки модели и признаков, реализовал логику формирования рекомендаций с учётом холодного старта и строгого соответствия структуры данных.
